# Customer Shopping Behavior Analysis

An end-to-end data analysis project on a retail customer shopping dataset (3,900 records) — covering data cleaning and feature engineering in Python, business-question analysis in SQL, and an interactive dashboard in Power BI.

## Project Overview

This project simulates a real analyst workflow: take a raw, messy dataset, clean and enrich it, load it into a relational database, answer specific business questions with SQL, and present findings visually for stakeholders.

**Pipeline:** CSV → Python (pandas) cleaning & feature engineering → MySQL → SQL analysis → Power BI dashboard

## Dataset

`customer_shopping_behavior.csv` — 3,900 rows, 18 columns covering customer demographics, purchase details, product categories, discounts, shipping, and purchase frequency.

## What's in this repo

| File | Description |
|---|---|
| `EDA.ipynb` | Data cleaning, missing value handling, and feature engineering in pandas |
| `Customer_Behavior.sql` | 10 business questions answered in SQL, including window functions and CTEs |
| `Customer_behavior.pbix` | Power BI dashboard built on the cleaned dataset |
| `customer_shopping_behavior.csv` | Raw source data |

## Data Cleaning & Feature Engineering (Python)

- Handled missing `review_rating` values by imputing the **median rating per product category** (rather than a single global median), since ratings vary meaningfully by category.
- Standardized column names (lowercase, underscores) for consistency.
- Engineered an `age_group` feature (Young Adult / Adult / Mid-aged / Senior) using quartile-based binning (`pd.qcut`), so age analysis isn't tied to arbitrary fixed cutoffs.
- Engineered a `purchase_frequency_days` feature, converting text frequency labels (e.g., "Fortnightly", "Monthly") into a numeric day count — enabling frequency comparisons that wouldn't be possible with the raw categorical labels.
- Identified that `discount_applied` and `promo_code_used` were perfectly correlated (identical in every row) and dropped the redundant column to keep the dataset lean.
- Loaded the cleaned dataset into MySQL via SQLAlchemy for downstream SQL analysis.

## Business Questions Answered (SQL)

1. Total revenue generated by male vs. female customers
2. Customers who used a discount but still spent above the average purchase amount
3. Top 5 products by average review rating
4. Average purchase amount: Standard vs. Express shipping
5. Do subscribed customers spend more? (avg spend and total revenue, subscribers vs. non-subscribers)
6. Top 5 products by discount-usage rate
7. Customer segmentation (New / Returning / Loyal) based on purchase history, using a CTE
8. Top 3 most purchased products within each category, using ROW_NUMBER() window function
9. Are repeat buyers (5+ previous purchases) more likely to subscribe?
10. Revenue contribution by age group

## Dashboard

`Customer_behavior.pbix` visualizes the cleaned dataset and key findings from the SQL analysis above — revenue breakdowns, category performance, and customer segments — for a non-technical, stakeholder-facing view.

## Setup / Reproducing This Project

1. Clone the repo and install dependencies:pip install pandas sqlalchemy pymysql
2. Set up a local MySQL database named `customer_behavior`.
3. Set database credentials as environment variables (do not hardcode credentials):
export DB_USER=root
export DB_PASSWORD=your_password
export DB_HOST=localhost
export DB_PORT=3306
export DB_NAME=customer_behavior
4. Run `EDA.ipynb` to clean the data and load it into MySQL.
5. Run the queries in `Customer_Behavior.sql` against the loaded table.
6. Open `Customer_behavior.pbix` in Power BI Desktop to explore the dashboard.
